# 可持续对话分析功能 - 实施计划

## 功能概述

模仿 Cursor/Kiro 等 Agent IDE 的 Side Panel 交互模式，将组件分析从"自动分析"改为"对话式分析"，用户选择组件后可以通过输入框进行自定义提问或使用默认分析。

## 核心交互流程

```
用户点击选择组件 → 选择页面组件 → 组件名称显示在输入框上方 
→ 用户输入问题（可选）→ 发送 → AI 分析 → 显示结果 → 继续对话
```

## 待确认问题

### [Question] Q1: 上下文限制策略
当对话历史超出 token 限制时，应该如何处理？
- A: 自动截断早期对话，保留最近 N 轮
- B: 提示用户清空对话历史
- C: 提示用户重新选择组件（清空所有上下文）

[Answer] 
- C: 提示用户重新选择组件（清空所有上下文）


### [Question] Q2: 默认分析内容
用户选择组件后直接发送（不输入问题），默认分析应该包含哪些内容？
- A: 完整分析（概述 + 业务逻辑 + 交互逻辑）- 与当前相同
- B: 简化分析（仅概述）- 鼓励用户提问
- C: 不分析，提示用户输入问题

[Answer] 
- B: 简化分析（仅概述以及核心业务逻辑）- 鼓励用户提问

### [Question] Q3: 对话历史持久化
对话历史是否需要持久化？
- A: 仅会话内存储（刷新页面后清空）
- B: 持久化到 localStorage（跨会话保留）
- C: 持久化到后端（跨设备同步）

[Answer] 
- A: 仅会话内存储（刷新页面后清空）


### [Question] Q4: 组件切换行为
用户在对话过程中选择新组件时，应该如何处理？
- A: 清空对话历史，开始新会话
- B: 保留对话历史，但标记组件切换
- C: 提示用户确认是否切换

[Answer] 
- A: 清空对话历史，开始新会话


### [Question] Q5: 流式输出
AI 回复是否需要流式输出（打字机效果）？
- A: 是，提升用户体验
- B: 否，等待完整响应后显示

[Answer] 
- A: 是，提升用户体验
