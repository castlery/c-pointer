# 组件代码分析器 - 用户故事文档

## 产品愿景

帮助产品经理、测试人员和开发人员快速理解 Castlery Joyboy 前端项目的组件实现细节，通过可视化选择和 AI 分析，降低代码理解门槛，提升团队协作效率。

## 目标用户

| 用户角色 | 使用场景 | 核心需求 |
|---------|---------|---------|
| 产品经理 | 需求设计、迭代规划 | 了解组件功能逻辑，评估改动影响范围 |
| 测试人员 | 测试用例设计、回归测试 | 理解组件行为，识别测试边界 |
| 开发人员 | 本地开发、代码审查 | 快速定位组件源码，理解依赖关系 |

## 用户故事列表

---

### Epic 1: 组件选择与识别

#### US-1.1 激活组件选择模式
**作为** 产品经理  
**我想要** 通过浏览器插件激活组件选择模式  
**以便** 开始在页面上选择我想要分析的组件

**验收标准：**
- AC-1.1.1 点击插件图标后，页面进入组件选择模式
- AC-1.1.2 选择模式激活时，插件图标显示激活状态
- AC-1.1.3 再次点击可退出选择模式

**优先级：** P0 (MVP)

---

#### US-1.2 悬停预览组件
**作为** 测试人员  
**我想要** 鼠标悬停在页面元素上时看到组件边框预览  
**以便** 确认我即将选择的组件范围

**验收标准：**
- AC-1.2.1 鼠标悬停时显示蓝色虚线边框
- AC-1.2.2 边框精确匹配组件的 DOM 边界
- AC-1.2.3 鼠标移开后边框消失

**优先级：** P0 (MVP)

---

#### US-1.3 点击选中组件
**作为** 产品经理  
**我想要** 点击页面元素来选中一个组件  
**以便** 对该组件进行代码分析

**验收标准：**
- AC-1.3.1 点击后显示绿色实线边框表示选中状态
- AC-1.3.2 选中后自动提取组件名称和文件路径
- AC-1.3.3 如果点击的不是 React 组件，自动向上查找最近的父组件

**优先级：** P0 (MVP)

---

#### US-1.4 识别组件类型
**作为** 开发人员  
**我想要** 系统自动识别组件属于 Fortress 组件还是业务模块组件  
**以便** 了解组件的来源和性质

**验收标准：**
- AC-1.4.1 识别 libs/fortress 下的 Fortress 组件
- AC-1.4.2 识别 libs/modules 下的业务模块组件
- AC-1.4.3 识别 libs/shared 下的共享组件
- AC-1.4.4 在选中组件时显示组件类型标签

**优先级：** P0 (MVP)

---

#### US-1.5 手动输入组件路径
**作为** 开发人员  
**我想要** 在自动识别失败时手动输入组件路径  
**以便** 仍然能够分析目标组件

**验收标准：**
- AC-1.5.1 提供输入框允许输入组件文件路径
- AC-1.5.2 支持路径自动补全建议
- AC-1.5.3 验证输入路径的有效性

**优先级：** P1

---

## 非功能性需求

### NFR-1 性能要求
- 组件选择响应时间 < 100ms
- 代码分析完成时间 < 30s
- 结果展示渲染时间 < 500ms

### NFR-2 兼容性要求
- 支持 Chrome 浏览器 90+
- 支持 React 17+ 页面

### NFR-3 可扩展性要求
- AI 服务支持未来切换到其他提供商
- 支持未来添加更多分析维度

### NFR-4 安全性要求
- 代码仓库访问在后端完成，不暴露给前端
- 支持 Git 凭证安全存储
